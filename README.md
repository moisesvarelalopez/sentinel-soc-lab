# 🛡️ Enterprise SOC Lab: Threat Hunting, Detection Engineering & Real Incident Triage

> **Microsoft Sentinel | Microsoft Defender XDR | KQL | Azure Logic Apps | MITRE ATT&CK**

---

## The Story (STAR Format)

### Situation
During a personal SOC lab built on Microsoft Sentinel to prepare for the SC-200 certification, I connected Microsoft Entra ID Protection and Microsoft Defender XDR data connectors to a real educational institution's tenant. Within hours, the workspace began ingesting live security alerts — not simulated data.

What started as a certification exercise became a real incident investigation.

### Task
Determine whether the alerts were noise or evidence of an active threat. If confirmed, reconstruct the full attack chain, document all findings with forensic rigor, and perform responsible disclosure to the affected institution — all without taking any direct action on systems I did not own.

### Action

**Phase 1 — Detection Engineering**  
I built two custom KQL analytic rules in Microsoft Sentinel:
- **NRT Rule** (`SOC - Password Spray Active Attack`): Near-real-time detection triggered on confirmed Password Spray alerts from Entra ID Protection, with JSON entity extraction using `parse_json()` and `mvexpand`.
- **Scheduled Correlation Rule** (`SOC - Multi-Signal Credential Attack Correlation`): Correlates 6 types of high-severity credential alerts within a 1-hour window for the same account, reducing alert fatigue and surfacing confirmed compromises with precision.

**Phase 2 — Threat Hunting**  
Using KQL against the `SecurityAlert` table, I mapped the full kill chain across 6 MITRE ATT&CK tactics:

| Phase | Tactic | Technique | Evidence |
|-------|--------|-----------|----------|
| 1 | Initial Access | T1110 - Password Spray | 145 alerts, 31 targeted accounts, 150+ attacker IPs across 20 countries |
| 2 | Defense Evasion | T1090 - Proxy/Tor | 40 alerts, Tor exit nodes and anonymous VPNs used to bypass geo-based Conditional Access |
| 3 | Persistence (Credential Access) | T1078 - Valid Accounts | 153 alerts, 34 accounts with confirmed unauthorized access (Atypical Travel, Malicious IPs) |
| 4 | Persistence | T1098 - Account Manipulation | 9 alerts, 8 Service Principal backdoors injected via automated Python script (`Python-urllib/3.11`) from IP `98.167.221.41` |
| 5 | Lateral Movement | T1566 - Phishing | 32 alerts, internal phishing campaign using compromised institutional mailboxes |
| 6 | Execution | T1204 - User Execution | 5 alerts, malware hosted in institutional OneDrive to distribute payloads via trusted internal links |

**Phase 3 — SOAR Automation**  
To demonstrate operational response capability, I built an automated triage pipeline:
- **Azure Logic App Playbook**: Triggered on Sentinel incidents, automatically adds triage comments to each incident for L1 analysts.
- **Managed Identity**: Configured with `Microsoft Sentinel Responder` RBAC role following the principle of least privilege. No hardcoded credentials.
- **Automation Rule**: Connected the playbook to trigger exclusively on incidents generated by my custom analytic rules.

**Phase 4 — Responsible Disclosure**  
Upon confirming an active breach with Day-0 persistence mechanisms being deployed, I compiled all IoCs, the full attack timeline, and technical recommendations into a formal security advisory, which I submitted directly to the institution's Digital Security team.

### Result
- **384 security alerts** correlated and classified across 6 MITRE ATT&CK phases.
- **34 unique compromised accounts** identified with supporting forensic evidence.
- **8 Service Principal backdoors** discovered on Day 0 (24 September 2026), within hours of deployment.
- **5-day active campaign** fully mapped from initial access to execution.
- **Full SOAR pipeline** built and tested end-to-end (Playbook → Managed Identity → Automation Rule).
- **Responsible disclosure** submitted with IoCs, kill chain documentation, and containment recommendations.
